# INDRA v4 — Live Severe-Weather Intelligence & 0–6 h Nowcasting for India

SIH 2026 · Problem statement SIH26084. INDRA is a single web app that runs a live background engine (radar, satellite, lightning, multi-model NWP, storm tracking, hazard fusion, alerting, self-verification) and streams it to a JARVIS-style command interface (light silver/ice glass theme, cyan holographic accents).

> INDRA alerts are **experimental screening alerts** generated by this software. They are not official IMD warnings. Official IMD products are shown separately and labelled as such.

## Run locally

Windows (easiest): double-click **`run_windows.bat`**. It creates `.venv`, installs `requirements.txt`, opens http://127.0.0.1:5000 and starts INDRA.

Windows (manual, Command Prompt in this folder):

```bat
py -m pip install -r requirements.txt
py app.py
```

> `ModuleNotFoundError: No module named 'scipy'` (or numpy/flask…) means the packages are not installed for the Python you are running (e.g. IDLE's F5). Run the `pip install -r requirements.txt` line above with that same Python. gunicorn does not run on Windows; `python app.py` uses Flask's threaded server, which is fine locally.

macOS / Linux: `./run_local.sh`, or:

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python app.py                 # http://127.0.0.1:5000
# or production-style
gunicorn -c gunicorn.conf.py app:app
```

Tests (offline, engine disabled): `pip install pytest && python -m pytest -q`

## Deploy on Render

1. Push this folder to a GitHub repo.
2. Render → New → Blueprint → select the repo (uses `render.yaml`), or New → Web Service with
   - Build: `pip install -r requirements.txt`
   - Start: `gunicorn -c gunicorn.conf.py app:app`
   - Health check path: `/api/health`
   - Env: `PYTHON_VERSION=3.12.7`
3. Optional secrets: `IMD_API_TOKEN`, `OPEN_METEO_API_KEY`.

Keep **one gunicorn worker** (already configured): the engine lives in that process and every request reads from its shared state. Concurrency comes from threads.

Render free tier notes: the service sleeps after ~15 min without traffic (first request after sleep takes ~1 min while the engine warms up), and the disk is ephemeral, so the SQLite alert/audit/verification history resets on each deploy or restart. Use a paid instance with a persistent disk (set `INDRA_RUNTIME_DIR` to the disk mount) for durable history.

## Accounts and tiers

Users must sign in before the dashboard opens. There are three ways in:

| Feature | Guest | Public (free) | Professional |
|---|---|---|---|
| Home (weather in plain words), location report, search, atlas | yes | yes | yes |
| Rain map (NASA GIBS IMERG), IR satellite, lightning, ground stations | yes | yes | yes |
| Official NDMA SACHET alerts, INDRA screening alerts (view) | yes | yes | yes |
| Live accuracy summary, Help | yes | yes | yes |
| Saved places, home place, feedback | - | yes | yes |
| Radar/Sat centre, Himawari, storm cell details, point nowcast | - | yes | yes |
| Command desk, national nowcast engine, impact, verification, system | - | - | yes |
| Per-model raw data, QC/hazard layers, satellite products, ack, replay, audit, exports, API docs | - | - | yes |

- Guest: one click, nothing saved, session lasts 24 h.
- Public: email + password.
- Professional: email + password + organisation + role + a professional access code.
  The access code comes from the `INDRA_PRO_ACCESS_CODE` environment variable. If that variable is not set, INDRA generates a code on first start, prints it in the server log and saves it to `data/runtime/pro_access_code.txt`. On Render, `render.yaml` generates the value automatically; open the service's Environment tab to read it.
- A signed-in public user can upgrade to professional from the account menu with the access code.
- Passwords are stored as salted hashes (Werkzeug); sessions are bearer tokens (public 30 days, professional 7 days, guest 24 h). Every API endpoint enforces the tier on the server, not just in the UI.
- On Render's free plan the disk is ephemeral, so accounts reset on every deploy or restart. Attach a persistent disk and point `INDRA_RUNTIME_DIR` at it to keep them.

## Your admin login

- Local: the bundled `.env` file sets `INDRA_OWNER_EMAIL` and `INDRA_OWNER_PASSWORD`. Run `python app.py`, choose Professional on the sign-in screen and sign in with them. The server prints `[INDRA] Owner admin ready: ...` at startup. Editing the password in `.env` and restarting changes it.
- Forgot it, or want another admin? `python create_admin.py you@example.com "New-Pass-2026" --owner` creates or resets an admin (omit `--owner` for a normal admin).
- `.env` is in `.gitignore`, so it is never pushed to GitHub. On Render, add `INDRA_OWNER_EMAIL` and `INDRA_OWNER_PASSWORD` in the service's Environment tab; the owner account is recreated on every start.

## Email verification, password reset and admin (v4.3)

- New public and professional accounts get a 6-digit email code (valid 24 h). Until the email is verified the account works at guest level; the dashboard shows a banner with a Verify button. Set `INDRA_REQUIRE_EMAIL_VERIFY=0` to turn this off.
- "Forgot password?" on the sign-in screen sends a reset code (valid 15 min, 5 attempts). The reply never reveals whether an email is registered. A reset signs the account out everywhere and marks the email as verified.
- Signed-in users can change their password and request professional access from the account menu (an admin approves or declines; no access code needed).
- Email delivery: set `INDRA_SMTP_HOST`, `INDRA_SMTP_PORT` (587 STARTTLS, or 465 with `INDRA_SMTP_SSL=1`), `INDRA_SMTP_USER`, `INDRA_SMTP_PASS`, `INDRA_SMTP_FROM`, and `INDRA_PUBLIC_URL` (used for one-click links in emails). Gmail works with an app password (`smtp.gmail.com`, 587).
- Without SMTP, INDRA runs in outbox mode: every email is stored in the Admin console's Email outbox tab and written to the server log. For demos only, `INDRA_EMAIL_DEMO_ECHO=1` also shows the code on screen. Do not enable it in production.
- Owner account: set `INDRA_OWNER_EMAIL` (and optionally `INDRA_OWNER_PASSWORD`, `INDRA_OWNER_NAME`). On startup INDRA creates that account as a verified Professional administrator. If no password is set, one is generated once, printed in the server log and saved to `data/runtime/owner_credentials.txt`; change it from the account menu. Other administrators cannot demote, suspend, sign out or delete the owner.
- More admins: Admin console → Users → Actions → "Make administrator" works on any account (public accounts are upgraded to Professional and marked verified). You can also list emails in `INDRA_ADMIN_EMAILS`. If neither the owner nor `INDRA_ADMIN_EMAILS` is set, the first professional account to register becomes the admin.
- Administrators always get every feature, regardless of their tier.
- Professional keys: Admin console → Pro keys issues personal keys (`PRO-XXXX-XXXX-XXXX`) with a label, an optional email lock, a use limit (1 / 5 / 25 / unlimited) and validity (7 days to no expiry). Keys can be emailed, copied and revoked; the list shows who used each one. The shared access code still works too.
- Admin console (shield icon in the rail, or account menu): overview KPIs, shared access code (copy / rotate), personal Pro keys, Add user (create a public, professional or admin account with a generated temporary password), users (search, filter, change tier, verify, suspend, sign out, make admin, send reset, delete), professional access requests, email outbox and the audit log. Admins cannot suspend, demote or delete themselves, and the last admin cannot be removed.

## Holographic interface (v4.3)

- INDRA Core: the orb next to the clocks (shortcut `J`) opens a live console that watches all feeds, logs new HIGH/CRITICAL screening alerts and official warnings as they arrive (kept separate), answers typed or spoken questions ("weather in Meerut", "any alerts", "how accurate", "storms", "near me") and can read replies aloud. `V` starts voice input.
- HUD frame over the map: live latitude/longitude rulers, cursor/zoom/scale readout, a target-lock reticle on the selected place and a ping on every map click.
- Feed vitals in the ticker (one bar per feed: green live, amber delayed, red unavailable), animated holographic panel edges, panel materialise transitions and a boot sequence. All motion turns off for users with "reduce motion" enabled.

## Accuracy, measured live

INDRA does not claim a fixed accuracy number. Every 10 minutes it downloads real METAR observations from about 70 Indian airport stations (aviationweather.gov), and every hour it scores the past 8 hours of each model forecast (Open-Meteo hindcast) against them: temperature within 2 °C, wind within 10 km/h, rain yes/no, POD and FAR. It compares 5 ways of combining models (each single model, equal mean, inverse-error weighted mean, median, best model per variable) and uses the best-scoring one as the "INDRA best estimate" on Home and in location reports. The latest scores are on the Accuracy page. Typical results: ~88% of temperatures within 2 °C, ~98% of winds within 10 km/h, rain yes/no ~97% overall but with low detection of showers. 99% accuracy is not realistic for severe-weather nowcasting anywhere, and INDRA shows its real numbers instead.

## What runs in the background

| Engine loop | Source | Interval | Label in UI |
|---|---|---|---|
| Precipitation ingest, QC, cell detection, tracking | NASA GIBS — GPM IMERG 30-min precipitation rate (WMS decoded with the official GIBS colormap to mm/h; dBZe derived via Z = 200R^1.6) | 5 min poll (new frame every 30 min, ~4–6 h latency) | LIVE if frame < 90 min old, otherwise DELAYED; dBZe is ESTIMATED |
| Geostationary IR loop over India | NASA GIBS — Himawari-9 AHI Band 13 clean IR | 10 min | LIVE (oblique view west of ~80°E) |
| Official alerts | NDMA SACHET (Common Alerting Protocol, `FetchAllAlertDetails`) | 3 min | OFFICIAL — shown in a separate layer/tab, never mixed with INDRA alerts |
| Satellite cold-cloud & rapid-cooling detection | EUMETSAT Meteosat IODC SEVIRI IR10.8 (WMS) | 5 min (new frame every 15 min) | LIVE; brightness temperature is ESTIMATED from imagery |
| Lightning | Blitzortung community network (websocket) | continuous, flushed every 3 s | LIVE when connected; it is community detection, not ILDS |
| Multi-model NWP | Open-Meteo: ECMWF IFS, NCEP GFS, DWD ICON, UKMO, ECMWF AIFS (each fetched independently with run time) | national grid hourly; any point on demand | LIVE with model run time |
| Hazard fusion & nowcast 0–6 h | INDRA (cells extrapolated + model diagnostics) | each scan | EXPERIMENTAL |
| Alerts | INDRA screening alerts (district + cell), escalation, expiry, ack, history | each scan | INDRA EXPERIMENTAL |
| Verification | precipitation self-verification of extrapolation vs. persistence (POD/FAR/CSI/bias) | each IMERG frame | LIVE, not independent ground truth |
| Official IMD | IMD API (requires token and IP whitelist) | 10 min | OFFICIAL when available, otherwise UNAVAILABLE |

Feeds that are not connected are shown as `NOT CONNECTED` / `UNAVAILABLE` — never simulated as live: IMD Doppler radar (DWR) network, INSAT-3DR/3DS (MOSDAC login required), IMD ILDS lightning, NCMRWF NCUM/NEPS, IMD WRF 3 km. The only simulated content is the clearly labelled `/api/replay/demo` SIMULATION used for training/replay.

## Honest limitations

- IMERG is a satellite precipitation estimate at 0.1° (~11 km) with ~4–6 h latency (Early run); it is not radar. Cells older than 90 min are drawn as grey dashed "DELAYED" history: no arrival ETA, no INDRA alert. Short-range nowcasting therefore relies on Meteosat/Himawari IR, lightning and NWP until a real-time radar feed (IMD DWR) is connected.
- NDMA SACHET's public feed gives a centroid and area but no polygon, so official alert footprints are approximate (equivalent-area circle + district-name matching). The alert text on SACHET is authoritative.
- National model grid is 1° (point reports use the exact location); 1–3 km resolution needs IMD/NCMRWF high-resolution data.
- Hazard scores and nowcasts are not validated against an independent event archive; the POD ≥ 0.80 target is shown as NOT DEMONSTRATED until such a validation exists.
- Blitzortung coverage over India is sparse; zero strikes may mean no detection rather than no lightning.
